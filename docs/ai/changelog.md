# Changelog

## Расположение

Файл `CHANGELOG.md` в корне проекта.

## Формат

Основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Группировка по неделям.

```markdown
# Audiobooks Changelog

Все значимые изменения проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## Неделя DD.MM — DD.MM.YYYY

### Добавлено

- Описание изменения

### Исправлено

- Описание изменения
```

### Категории

- **Добавлено** — новая функциональность
- **Изменено** — доработки существующего
- **Исправлено** — багфиксы
- **Удалено** — удалённая функциональность

Пустые категории не указываются.

## Принципы формирования записей

### Язык

Записи пишутся на **русском языке**. Технические термины (имена компонентов, эндпоинтов,
хуков, пропов) остаются на английском.

### Классификация

Классифицировать по **смыслу сообщения коммита**, не по эмодзи.
Эмодзи — подсказка, но не определяющий фактор.

### Пользовательская ценность

Описание должно отражать пользовательскую ценность, а не пересказывать коммит.

Плохо: `Добавлен хук useKeyboardShortcuts`
Хорошо: `Управление плеером с клавиатуры (пробел — пауза, стрелки — перемотка)`

Для исправлений описывать **что было сломано**, а не как починили:

Плохо: `Исправлен метод сортировки`
Хорошо: `Исправлена сортировка книг по сериям`

### Объединение коммитов

Несколько коммитов по одной задаче объединяются в **одну запись**.
Итеративные фиксы не перечисляются отдельно.

### Незавершённые фичи

Если функциональность ещё в разработке — **не включать** в changelog до завершения.

### Откатанные изменения

Если функциональность была добавлена, а затем откатана — в changelog
попадает только **итоговое состояние**.

### Что НЕ включать

- Внутренний тулинг: prettier, eslint, форматирование
- Обновления зависимостей (`npm audit fix`, upgrade TypeScript и т.п.)
- Документация (CLAUDE.md, docs/, README)
- CI/build изменения, .gitignore
- Внутренний рефакторинг, не меняющий поведение

### Ссылки на задачи

Если коммит связан с GitHub Issue, можно добавить `#123` в конце записи. Это опционально.
