# Вспомогательные модули

## series

Серии книг. Путь: `backend/src/series/`.

- **Хранилище:** файл `data/series.json`
- Поддержка старого формата (`author_id`) и нового (`authors[]`)
- `remove(seriesId)` — удаление серии + очистка из всех книг через `booksService.edit()`

## persons

Базовый сервис для авторов и чтецов. Путь: `backend/src/persons/`.

- **Хранилище:** `data/authors.json`, `data/readers.json`
- CRUD с UUID: `get(type)`, `create(type, name)`, `edit(type, id, name)`, `remove(type, id)`

## authors / readers

Обёртки над `PersonsService` для конкретного типа. Все эндпоинты — `@Admin()`.

## sign-up

Регистрация. Путь: `backend/src/sign-up/`.

- `signUp(login, password, name, captchaToken)` — проверка уникальности логина, reCAPTCHA v3, создание пользователя с `enabled: false`
- `check(login)` — проверка доступности логина
- `BadRequestException` при дублировании или ошибке капчи

## common

Утилиты. Путь: `backend/src/common/`.

| Метод | Описание |
|---|---|
| `readJSONFile(name)` | Чтение из `DataDir`, `undefined` если файл отсутствует |
| `writeJSONFile(name, data)` | Атомарная запись: копия → `.bak`, запись → `.tmp`, rename |
| `generateID()` | UUID v4 uppercase |
| `getExtensionByMimeType(type)` | jpeg → jpg, png → png |
| `extractImageFromID3tag(file)` | Парсинг ID3 через `node-id3` |
| `getDuration(filename)` | Длительность MP3 в секундах |

## external-playlist

Парсинг внешних плейлистов. Путь: `backend/src/external-playlist/`.

Поддерживаемые форматы (пробует все по очереди):
1. **PlayerJS** — regex `file: [...]` или `file: "url"` в HTML
2. **DLE** — HTML-комментарий `<!--dle_audio_begin:...-->`
3. **GraphQL/Nuxt** — `window.__NUXT__` JSON-состояние в HTML

CORS: добавляет `Origin` и `Referer` заголовки к запросам.

## telegram / tg-bot

Telegram-интеграция. Путь: `backend/src/telegram/`, `backend/src/tg-bot/`.

- `TelegramService` — API операции, проверка членства в чате
- `TgBotService` — обработчик команд Telegraf, реализует `OnModuleInit`
- Автозапуск бота отключён (`launchOptions: false` в `app.module.ts`)
- `TgBotService.onModuleInit()` запускает бота вручную с retry каждые 30 секунд при ошибке
- Backend не падает если Telegram API недоступен

## log

Клиентское логирование. Путь: `backend/src/log/`.

- `POST /log` — `@Public()` эндпоинт, записывает данные в серверные логи

Публичный намеренно: двое из трёх писателей работают до того, как появился токен — страница логина
сообщает о сбоях входа через Telegram, а перехватчик отказов API отчитывается в том числе при негодном
токене. Третий писатель — диагностика плеера, она уходит через `sendBeacon`, который заголовок с токеном
поставить не может.

Раз аутентификация воротами быть не может, приём ограничен иначе:

- тело описано `LogDto` — три необязательные группы (`telegramLogin`, `apiError`, `playerDiagnostics`),
  и хотя бы одна обязана быть, иначе 400. Первые две свободной формы, третья описана точно; записи
  диагностики внутри неё намеренно оставлены свободными — они несут поля того события, которое записали
- `ValidationPipe` с `whitelist` и `forbidNonWhitelisted` на контроллере: незаявленный ключ даёт 400, а не
  попадает в журнал. Глобальный пайп такого не делает, и навешивать это на всё приложение незачем
- свой парсер тела на маршруте, лимит 64 КБ — под предел `sendBeacon`; он отвечает 413, не доходя до
  контроллера. Из-за него в `app.ts` **все** парсеры регистрируются вручную (`bodyParser: false` при
  создании приложения): маршрутный парсер, повешенный поверх нестовского, занял бы его место по совпадению
  имени слоя, и тело перестало бы разбираться на всех остальных маршрутах. Порядок регистрации несущий:
  маршрутный парсер обязан идти раньше общего, иначе тело разберёт общий со своим лимитом, а маршрутный
  молча выйдет — тело уже прочитано
- `ThrottlerGuard` на контроллере, 30 запросов в минуту с адреса: настоящий клиент шлёт пачку раз в
  30 секунд, всплеск даёт только перехватчик ошибок, когда разом падает несколько запросов.
  `ThrottlerModule.forRoot` живёт в `app.module.ts`, а не в модуле логов: модуль троттлера глобальный,
  и его настройка из фича-модуля стала бы общеприложенческой втихую. Ключ лимита — адрес клиента, поэтому
  в `app.ts` выставлен `trust proxy: ['loopback', 'uniquelocal']`: без него за обратным прокси все клиенты
  считались бы одним. Нужны оба набора — петля закрывает nginx на хосте, частные диапазоны — шлюз
  docker-сети; в `proxy-addr` это разные наборы, и `uniquelocal` петлю не включает

Отправка через `sendBeacon` ответа не видит, так что ни 400, ни 413, ни 429 клиент не заметит: браузер
рапортует об успехе в момент постановки в очередь, а буфер диагностики после этого очищается. В журнале
из них виден только отказ парсера тела — 400 от валидации и 429 от троттлера Nest не логирует. Отсюда
практическое следствие: лишнее поле, добавленное клиентом раньше выката бекенда, гасит всю диагностику
молча и бесследно.

Что в журнал **не** попадает: перехватчик отказов API вырезает из аргументов запроса поля, чьи имена
похожи на секреты (`redactSecrets` во фронтенде) — иначе неудачный вход отправлял бы туда пароль
